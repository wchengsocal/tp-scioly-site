# CLAUDE.md — Design Standards for This Project

You are acting as the design lead for this website. Every visual decision should look like it was made by a deliberate human designer with taste, not generated by default. Follow these rules on every task that touches UI.

---

## 1. Never look vibe-coded

"Vibe-coded" design is the generic look AI tools produce when no one makes real decisions. It is instantly recognizable — people say they can smell an AI-generated frontend from a mile away — and it must be avoided.

### The banned hero pattern

There is one specific hero layout that appears on nearly every AI-generated site. Do not build it:

```
        [ small pill badge with icon ]
     Huge Bold Centered Headline Here
   Second line in a purple-blue gradient
   One line of vague subtext under it here
     [ Filled button ]  [ Outline button ]
      · icon · icon · icon · icon (trust row)
```

Every element of that stack is a tell: the pill badge above the headline, the two-line headline where line two is gradient text, the primary-filled + secondary-outline button pair, and the row of tiny gray trust icons underneath. Design an actual hero for the actual subject instead.

### Banned unless the user explicitly asks

**Color**
- Purple, violet, magenta, and indigo as primary or accent colors (`#8B5CF6`, `#7C3AED`, `#6366F1`, `#A855F7`). This is the single strongest tell.
- Purple→magenta, purple→blue, or purple→pink gradient backgrounds filling a hero or section.
- Gradient text on headlines via `background-clip: text` as a default move.
- Near-black (`#0A0A0A`) background whose only color is one purple/blue accent.
- Glowing gradient orbs blurred behind centered content.

**Layout & components**
- The three-stat row directly under the hero — big number, tiny gray caption, repeated three times (`25%` / `95%` / `2025`) — especially with invented or meaningless numbers.
- Three-column feature grids of icon + bold title + two lines of gray text, repeated for every section.
- Glassmorphism cards (blurred translucent panels, 1px white border) used everywhere without purpose.
- Emoji standing in for icons (🚀 ✨ 💡 🎯).
- Everything centered, every section the same width, every card the same size.
- Default shadcn/Tailwind look left unmodified: `rounded-xl` on everything, default slate palette, default spacing scale.

**Copy**
- "The Future of X is Here", "Start it. Build it. Launch it.", "Transform your X with AI".
- Supercharge / Unlock / Seamless / Effortless / Next-level / Revolutionizing / Cutting-edge.
- "Why Choose [Product]?" as a section heading.
- Subheadlines that describe nothing: "Revolutionizing X by leveraging advanced Y to deliver Z."

**Instead:**
- Choose a palette derived from the subject of the site (its world, materials, environment). Name the hex values in a comment at the top of the stylesheet and stick to them.
- Commit to one memorable signature element per page — a distinctive hero treatment, an unusual layout structure, a purposeful animation — and keep everything else disciplined.
- Asymmetry, editorial layouts, and generous whitespace read as human. Perfectly symmetric centered stacks read as generated.

## 2. Typography

- Never default to system-ui, Arial, or unstyled Inter. Every project gets a deliberate type pairing:
  - One characterful display face for headlines (used with restraint).
  - One highly readable body face.
  - Optionally a monospace for labels, data, or captions.
- Load real fonts (Google Fonts or self-hosted). Set an explicit type scale — sizes, weights, line-heights, letter-spacing — instead of relying on framework defaults.
- Headlines are a design element, not just big text: consider weight contrast, tightened letter-spacing, or mixed sizes where appropriate.
- Body text: 16–18px minimum, line-height ~1.6, max line length ~70ch.

## 3. Responsive: desktop AND mobile, always

- Every page must be fully usable and beautiful from 320px to 1440px+. No horizontal scroll at any width.
- Use fluid techniques by default: `clamp()` for type scale, CSS grid/flex with wrapping, relative units.
- Test these breakpoints on every change: 320, 375, 768, 1024, 1440.
- Touch targets ≥ 44px on mobile. Hover-only interactions must have a mobile equivalent or degrade gracefully (e.g., custom cursors and magnetic effects off on touch devices).
- Navigation must collapse sensibly on mobile — no cramped desktop nav shrunk down.

## 4. Follow user-provided references exactly

- When the user provides screenshots, links, or named sites as design references, treat them as the source of truth. Extract and match: palette, type choices, spacing rhythm, corner radii, shadow style, motion feel.
- Match the reference's *decisions*, not just its vibe — if their reference uses sharp corners and one accent color, do not add rounded cards and a second accent.
- If a reference conflicts with a rule in this file (e.g., the reference is purple), the user's reference wins. Say you're following it.
- If no reference is given, state your design direction in one short paragraph before building so it can be corrected early.

## 5. Motion

- Motion must be purposeful: page-load sequence, scroll reveals, or micro-interactions that reinforce the content — not decoration sprinkled everywhere.
- Prefer one orchestrated moment over many scattered effects.
- Use easing curves that feel physical (`cubic-bezier(.22,1,.36,1)` style), never `linear` for UI motion.
- Always respect `prefers-reduced-motion` — provide a static fallback.
- No animation should block reading or interaction, and nothing should loop distractingly in the user's peripheral vision.

## 6. Always check your work when done

After completing any UI change, before reporting done:

1. **Render and look at it.** Open the page (screenshot or preview) rather than assuming the code is right.
2. **Walk the breakpoints** listed in section 3 and fix any overflow, wrapping, or spacing breakage.
3. **Audit against section 1.** Ask directly: if a stranger saw this screenshot, would they say "that's AI-generated"? Check specifically — any purple? gradient headline text? pill badge over a centered hero? a three-stat row? two buttons side by side? If yes to any, redesign that element rather than tweaking it.
4. **Check the details**: focus states visible, contrast ≥ WCAG AA, images have alt text, no layout shift on font load, console free of errors.
5. **Chanel pass**: remove one decorative element that isn't earning its place.
6. Only then summarize what was built and flag any tradeoffs.

## 7. Copy standards

- Write copy specific to this site's actual subject — real names, real numbers, real details. Placeholder copy must be marked `<!-- TODO: replace -->`.
- Buttons say exactly what they do ("Sign up for tryouts", not "Get Started").
- No filler adjectives. Specific beats clever.
